# Шаг 13. README, демонстрация и масштабирование

## Цель

Подготовить все материалы, которые прямо запрошены в задании, и объяснить принятые решения.

## Что сделать

1. Написать корневой README со следующими разделами:
   - назначение проекта;
   - архитектурная схема;
   - стек и причины выбора;
   - требования к окружению;
   - запуск через Docker Compose;
   - миграции и seed;
   - вымышленные демонстрационные учётные данные;
   - URL frontend, Swagger и health endpoints;
   - запуск тестов;
   - сценарий демонстрации;
   - известные ограничения.
2. Описать демонстрационный сценарий:
   - вход клиентом;
   - просмотр всех филиалов;
   - выбор филиала и периода;
   - попытка прямого доступа к чужим данным;
   - вход администратором;
   - запуск импорта дважды;
   - подтверждение отсутствия дубликатов.
3. Подготовить скриншоты или короткую запись без реальных данных и секретов.
4. Кратко описать масштабирование до 500+ компаний и тысяч филиалов:
   - индексы и возможное partitioning PostgreSQL по дате;
   - фоновые задачи и очередь для импорта;
   - блокировки/дедупликация задач и повторяемость обработки;
   - ограничение параллелизма и rate limits внешних API;
   - Redis cache для часто повторяемых агрегатов при необходимости;
   - read replicas и наблюдаемость;
   - переход к ClickHouse для больших объёмов сырых событий и тяжёлой аналитики, а не автоматически из-за числа компаний.
5. Объяснить, что PostgreSQL остаётся источником транзакционных данных, пользователей и прав доступа даже при добавлении ClickHouse.
6. Перечислить ограничения первой версии:
   - ручной запуск импорта;
   - один внешний источник;
   - упрощённое управление пользователями;
   - отсутствие полноценного модуля отзывов;
   - дневные данные без сложной модели часовых поясов;
   - отсутствие production secrets management.

## Критерии готовности

- Новый разработчик может запустить проект только по README.
- Все пункты раздела «Что предоставить» из ТЗ закрыты.
- Масштабирование описано конкретно и без преждевременного внедрения ClickHouse.
- Демонстрационные материалы не содержат чувствительных данных.
