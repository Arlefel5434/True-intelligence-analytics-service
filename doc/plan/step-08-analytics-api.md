# Шаг 8. REST API филиалов и аналитики

## Цель

Предоставить frontend типизированные endpoints для выбора компании, филиала, периода и отображения агрегатов.

## Что сделать

1. Реализовать endpoints:
   - admin-only список компаний;
   - список доступных филиалов;
   - агрегированная аналитика;
   - временной ряд выбранного показателя.
2. Для администратора требовать выбранную компанию; для клиента определять её из текущего пользователя.
3. Поддержать фильтры:
   - `branchId` — необязателен, отсутствие означает все доступные филиалы компании;
   - `from` и `to` — обязательный или безопасный дефолтный период;
   - `metric` — показатель графика из разрешённого enum.
4. Рассчитывать totals:
   - счётчики через `SUM`;
   - рейтинг как `SUM(rating * newReviewCount) / SUM(newReviewCount)`;
   - `null`, если новых отзывов нет, а не искусственный ноль.
5. Для графика группировать выбранный показатель по дате сразу по всем выбранным филиалам.
6. Валидировать:
   - формат и порядок дат;
   - максимальную длину периода;
   - принадлежность филиала доступной компании;
   - допустимое имя показателя.
7. Возвращать DTO со стабильным форматом: фильтры, totals, series и metadata.
8. Документировать endpoints и ошибки через Swagger/OpenAPI.
9. Генерировать типизированный клиент в `packages/api-client`; не редактировать сгенерированный код вручную.

## Критерии готовности

- Запрос без `branchId` агрегирует все филиалы выбранной компании.
- Запрос с `branchId` возвращает только один доступный филиал.
- Данные разных компаний никогда не смешиваются.
- Сгенерированный клиент проходит TypeScript-проверку.
