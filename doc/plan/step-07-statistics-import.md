# Шаг 7. Идемпотентный импорт показателей

## Цель

Получать данные из mock-провайдера, сохранять их без дубликатов и фиксировать результат каждого запуска.

## Что сделать

1. Реализовать admin-only endpoint `POST /imports/statistics` с включительным диапазоном `from..to`.
2. Создать клиент внешнего источника с:
   - timeout;
   - передачей API-ключа;
   - обработкой пагинации;
   - ограниченным числом повторов только для безопасных временных ошибок.
3. До импорта создать `ImportRun` со статусом `RUNNING`.
4. Для каждой записи:
   - сопоставить внешний филиал с локальным;
   - валидировать данные;
   - выполнить upsert по `(source, externalId)`;
   - не создавать вторую запись для той же пары `(branchId, date)`.
5. Выполнять запись страницы или разумного batch в транзакции; не держать одну долгую транзакцию на весь внешний запрос.
6. После завершения сохранить число созданных, обновлённых и пропущенных записей. Неизвестный внешний филиал пропускать с предупреждением, не создавая его автоматически.
7. Обрабатывать данные атомарно на уровне страницы: некорректная запись отклоняет страницу целиком, но не мешает обработать следующие страницы.
8. Завершать импорт как `COMPLETED`, `COMPLETED_WITH_WARNINGS` или `FAILED` согласно фактически сохранённым страницам; всегда сохранять безопасное описание ошибок.
9. Предотвратить одновременный импорт одного источника и пересекающегося диапазона либо явно сериализовать такие запуски.
10. Возвращать результат, позволяющий UI сообщить, что повторный импорт не создал дубликатов.

## Критерии готовности

- Два запуска одного диапазона оставляют одинаковое количество дневных записей.
- Ошибка mock-провайдера не оставляет импорт в статусе `RUNNING`; частичный успех отражается как предупреждение.
- Клиент не может запустить импорт.
- История запусков пригодна для диагностики.
