# Шаг 10. Аналитический дашборд

## Цель

Реализовать основной пользовательский сценарий: от выбора доступных данных до просмотра итогов и динамики.

## Что сделать

1. Для администратора добавить обязательный выбор компании.
2. Для клиента скрыть выбор компании и показать название его компании как контекст.
3. После определения компании загрузить филиалы и предоставить варианты:
   - `Все филиалы`;
   - конкретный филиал.
4. Добавить выбор включительного периода `from..to` с разумным дефолтом.
5. Показать карточки:
   - просмотры;
   - переходы на сайт;
   - звонки;
   - построенные маршруты;
   - средний рейтинг;
   - количество отзывов.
6. Добавить выбор показателя графика и построить временной ряд в Recharts.
7. Реализовать отдельные состояния:
   - первоначальная загрузка;
   - обновление фильтров;
   - пустой период;
   - ошибка API;
   - успешный результат.
8. Для администратора добавить компактное действие запуска импорта с диапазоном и понятным итогом `created/updated/skipped`.
9. Синхронизировать фильтры с URL query parameters, чтобы состояние можно было воспроизвести после перезагрузки.
10. Обеспечить базовую адаптивность и доступность: labels, клавиатурная навигация, читаемые состояния focus и корректные числовые форматы.

## Критерии готовности

- `Все филиалы` показывает общий результат по филиалам одной компании.
- Выбор филиала меняет карточки и график.
- Пользователь всегда понимает, за какую компанию, филиал и период показаны данные.
- UI не показывает клиенту недоступные административные действия.
